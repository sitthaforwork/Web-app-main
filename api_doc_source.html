1. ภาพรวมและมาตรฐานการเชื่อมต่อ (API Standard Overview)

ระบบ Northwind BMS ได้รับการออกแบบตามสถาปัตยกรรม Decoupled RESTful API Architecture ซึ่งแยกส่วนหน้าบ้าน (Front-End) และหลังบ้าน (Back-End) ออกจากกันอย่างชัดเจน โดยสื่อสารผ่านโปรโตคอล HTTP/HTTPS ด้วยรูปแบบข้อมูล JSON มาตรฐาน

1.1 ข้อมูลการเชื่อมต่อหลัก

คุณลักษณะ รายละเอียด
Base URL /api (เช่น https://your-domain.com/api หรือ http://localhost/Web%20App/api)
Format application/json; charset=utf-8 สำหรับทั้ง Request Body และ Response
Authentication JSON Web Token (JWT) ส่งผ่าน Header: Authorization: Bearer {token}
SQL Security เขียนด้วย PDO Prepared Statement และ Bind Parameter ทุก Query ป้องกัน SQL Injection
HTTP Methods GET (อ่าน), POST (สร้าง), PUT (แก้ไข), DELETE (ลบ), OPTIONS (Preflight)

1.2 โครงสร้าง Response มาตรฐาน (Unified Response Schema)

ตัวอย่าง: การตอบกลับกรณีสำเร็จ (HTTP 200 / 201) 200 OK
{
  "success": true,
  "message": "ดึงข้อมูลสินค้าสำเร็จ",
  "data": [ ... ]
}
ตัวอย่าง: การตอบกลับกรณีข้อมูลไม่ผ่านการตรวจสอบ (HTTP 422) 422 Unprocessable Entity
{
  "success": false,
  "message": "ข้อมูลไม่ผ่านการตรวจสอบความถูกต้อง",
  "errors": [
    "กรุณากรอกชื่อสินค้า",
    "ราคาสินค้าต้องไม่ต่ำกว่า 0 บาท"
  ]
}

6. โมดูลข้อมูลหลัก (Master Data APIs — 5 ตารางหลัก)

6.1 หมวดหมู่สินค้า (Categories — tb_categories)

Method & Endpoint หน้าที่การทำงาน ตัวอย่างพารามิเตอร์
GET /api/categories ดึงหมวดหมู่ทั้งหมดพร้อมจำนวนสินค้า (productCount) -
GET /api/categories/{id} ดึงข้อมูลหมวดหมู่รายตัวตาม ID id: 1
POST /api/categories เพิ่มหมวดหมู่ใหม่ {"name": "เครื่องดื่ม", "description": "น้ำผลไม้ ชา กาแฟ"}
PUT /api/categories/{id} แก้ไขข้อมูลหมวดหมู่ {"name": "เครื่องดื่ม", "description": "..."}
DELETE /api/categories/{id} ลบหมวดหมู่สินค้า id: 10

6.2 ลูกค้า (Customers — tb_customers)

Method & Endpoint หน้าที่การทำงาน ตัวอย่างพารามิเตอร์
GET /api/customers ดึงทะเบียนลูกค้าทั้งหมด (รองรับ ?search=, ?country=) ?country=Germany
GET /api/customers/countries ดึงรายชื่อประเทศทั้งหมด 21 ประเทศ สำหรับใส่ Dropdown -
POST /api/customers เพิ่มลูกค้าใหม่ {"name": "...", "contactName": "...", "city": "...", "country": "..."}
PUT /api/customers/{id} แก้ไขข้อมูลลูกค้า JSON โครงสร้างลูกค้า
DELETE /api/customers/{id} ลบข้อมูลลูกค้า id: 92

6.3 ผู้จัดจำหน่าย (Suppliers — tb_suppliers)

Method & Endpoint หน้าที่การทำงาน ตัวอย่างพารามิเตอร์

8. ตารางรหัสสถานะ HTTP (HTTP Status Codes Reference)

HTTP Code Status ความหมายและการใช้งานในระบบ
200 OK การร้องขอสำเร็จ (เช่น ดึงข้อมูลสำเร็จ, แก้ไขสำเร็จ, ลบสำเร็จ)
201 Created สร้างข้อมูลใหม่ในฐานข้อมูลสำเร็จ (POST /products, POST /orders)
400 Bad Request คำขอไม่ถูกต้อง เช่น ไม่ส่ง JSON Body หรือข้อมูลผิดรูปแบบ
401 Unauthorized ไม่พบ Token หรือ Token หมดอายุ / ชื่อผู้ใช้หรือรหัสผ่านผิด
403 Forbidden ไม่มีสิทธิ์ในการเข้าถึงทรัพยากรนั้น (เช่น เข้า setup_database โดยไม่มีคีย์)
404 Not Found ไม่พบ Endpoint หรือไม่พบ Record ที่ระบุด้วย ID
422 Unprocessable Entity ข้อมูลไม่ผ่านการตรวจสอบความถูกต้อง (Validation Error)
500 Internal Server Error เกิดข้อผิดพลาดในการประมวลผลคำสั่งหรือเชื่อมต่อฐานข้อมูลล้มเหลว
สรุปการปฏิบัติตามเกณฑ์โครงงาน:
เอกสารนี้จัดทำขึ้นตรงตามข้อกำหนดที่ 4 ของวิชาการพัฒนา Web Application โดยครอบคลุม Endpoint ทั้งหมด 30+ ตัว, ระบุ URL, Method, Header, Parameters, Response JSON และตัวอย่างข้อมูลจริงครบถ้วนสมบูรณ์
